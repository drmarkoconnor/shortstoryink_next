# Writing workspace usability — next release after PR #6

Mark explicitly requested publication of the current PR #6 and a separate PR for the following improvements. This branch starts from merge commit 3cd3241bf56c9ccd75b4b95e18a4600060898c64. Do not reopen or duplicate PR #6; do not deploy this branch as production while unfinished.

## Scope

1. Paragraph-aware manuscript editing: Enter creates a paragraph; Shift+Enter a soft line break; Tab applies one standard first-line indent; Shift+Tab removes it; Escape returns keyboard focus to the editing toolbar. Real paragraph formatting, not inserted runs of spaces. Preserve predictable undo/redo, input methods, selection and save/conflict recovery.
2. Persistent manuscript tree: alongside writing/cards/reading on desktop; collapsible on smaller screens. Separate keyboard focus from opening a section. Expand/collapse without disturbing prose. Keep selected item, parent path and folder destination visible. Retain full-path Move to and pointer/touch alternatives to dragging.
3. Compact organising cards: title, short synopsis, status, optional folder count; reduce permanent action furniture, not legibility. Compact/Comfortable density.
4. Easier beginnings: continue an existing project, create a new project, or write/send a single piece. Short piece, chaptered work and blank are optional starter arrangements, not plot templates.
5. Indentation and paragraph/soft-break distinctions must survive cloud saves, immutable revisions, named/safety snapshots, conflict copies, reading and Word/print exports. Existing text/history/submissions must not be retrospectively reinterpreted or rewritten.

## Release and safety

PR #6 was released as early access following Mark's explicit instruction. Its keep-a-separate-copy warning remains. Independent encrypted off-primary backup and successful restoration are NOT verified. An automated round trip through real Netlify Identity is also not yet recorded; neither an anonymous runtime probe nor the isolated browser fixture is equivalent. These items remain open and must not be silently described as passed.

Working projects remain owner-private, including from editors. Only deliberately submitted copies enter editorial feedback and selective group sharing. Never grant editors general access to working manuscripts to simplify testing.

## Required evidence

Use synthetic data and automated browser/database tests, not repeated manual editor/writer logins for Mark. Cover paragraph keys, keyboard exit, undo/redo, single Enter dialogue, soft breaks, exact saves, formatting-only conflicts, snapshot restoration, old-text compatibility, compiled Word/PDF paragraph structure, persistent tree selection, full-path movement, failed-save navigation, cycles and cross-project denial. Render/check exports; a successful build is not proof of correct pagination.

Changes stay in a draft PR until the new tests and deployed preview checks are recorded. Mark receives screenshots/recording and at most one optional short writer usability check. No real-user mail or production manuscript changes in test runs.
