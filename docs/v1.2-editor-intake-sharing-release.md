# v1.2 editor intake and group sharing — release and rollback notes

## Invariants

- Existing writer-led submission remains available and unchanged.
- A manuscript is private until its writer (or an editor acting on the writer's explicit request) chooses recipients.
- ABU is never a sharing group.
- Recipient access always requires both an explicit grant and current membership of the manuscript's real group.
- Peer readers never gain access to editorial feedback items or summaries.
- Reader responses are whole-piece responses, visible only to manuscript author, responder and editors.
- Editor-imported manuscripts belong to the nominated writer and enter the ordinary feedback/revision chain.
- An imported manuscript can be corrected only before editorial review or sharing has begun.

## Release gates

1. Migration 002 applies cleanly to the Deploy Preview database branch.
2. Database regression tests pass, including same-group-but-unselected denial.
3. Typecheck, lint and production build pass.
4. Automated HTTP rehearsal covers editor intake, selected sharing, reader response and revocation without sending real email.
5. Editor checks the intake screen on Deploy Preview using the normal editor account.
6. Production snapshot exists before merge.

## Emergency privacy rollback

If there is any doubt about selective-sharing privacy, restore the original restrictive
submission rule immediately. This leaves the v1.2 tables in place but makes shared
manuscripts unreadable to peers while preserving their rows for diagnosis.

```sql
drop policy if exists "private workshop submissions" on public.submissions;
create policy "private workshop submissions" on public.submissions as restrictive
for select to public using (
  (select studio_auth.uid()) is not null and
  (
    author_id = (select studio_auth.uid())
    or (select private.workshop_is_teacher())
  )
);

drop policy if exists "share recipients visible only to participants"
  on public.submission_share_recipients;
create policy "share recipients emergency lock"
  on public.submission_share_recipients
for select to public using (
  (select studio_auth.uid()) is not null
  and (
    (select private.workshop_is_teacher())
    or private.submission_is_owned_by(submission_id,(select studio_auth.uid()))
  )
);

drop policy if exists "reader responses visible only to author responder or editor"
  on public.reader_responses;
create policy "reader responses emergency lock"
  on public.reader_responses
for select to public using (
  (select studio_auth.uid()) is not null
  and (
    (select private.workshop_is_teacher())
    or private.submission_is_owned_by(submission_id,(select studio_auth.uid()))
  )
);
```

After the database privacy lock is applied, roll the application back to the previous
production commit. Do not drop the new tables during an incident; preserving them avoids
destroying reader responses or audit information while the cause is investigated.
