# Writer Projects v1.3 — implementation and release gate

Basis: Mark's approved three-page Writer Projects brief, 30 September 2026, plus the explicit early-compile request. This is an additive extension to v1.2, not a replacement writing platform. Use one canonical PR; do not recreate the parallel PR #4/#5 problem.

## First-release scope

Private account-saved projects; folder/section hierarchy; outline, organising cards and manuscript reading; named section and whole-project snapshots; preview and reversible restore; stale-device conflict preservation; owner-only text/history/export access; local unsent recovery; recoverable removal; plain-text/archive export; fixed selected-section submission copies; early Word and print/PDF compilation.

Projects are enabled automatically only on Deploy Previews. Production needs WRITER_PROJECTS_ENABLED=true after all release gates pass. WRITER_PROJECTS_ENABLED=false disables both entry and API. Existing quick submission, editor intake, v1.2 sharing and published feedback are unchanged.

## Manuscript lifecycle

Autosave creates immutable section revisions after a pause, with a server acknowledgement. Local recovery is not a cloud acknowledgement. Request retries reuse the same save payload. A stale revision stores a separate conflict revision without replacing the current one. Structural moves have their own version check. Snapshots and compiles capture a coherent project state under a database lock. A restore first takes a safety snapshot, then creates new working revisions. Old snapshots and submitted copies never change.

Named and safety snapshots are retained until deliberate removal; automatic recovery snapshots retain 30 days. Older ordinary saves are coalesced into five-minute recovery points after a day and pruned after 30 days unless referenced by a current section, snapshot or compiled copy. Snapshot records reference immutable revisions instead of duplicating manuscript text. Archived projects remain recoverable. Hard deletion/account data deletion remains governed by the existing account process; no background deletion of real projects is introduced.

Working projects are owner-private even from editorial roles. Export and API guards enforce the same boundary. Sending a compiled extract creates a normal immutable submission using the existing guarded submission routine and stores its compile provenance; only that submission may subsequently be shared. A new submitted revision is an explicit action and starts private.

## Compile — verified submission guidance, 30 September 2026

A practical prose preset is Times New Roman 12 pt, double spacing, A4, 25.4 mm margins, left alignment and paragraph indentation. These are adjustable defaults, NOT universal acceptance criteria.

- Janklow & Nesbit UK: readable 12-point font, double-spaced sample; Word preferred, PDF accepted. https://www.janklowandnesbit.co.uk/submissions
- Blake Friedmann: Word .doc/.docx, not PDF/Pages; preferably 1.5 spacing; numbered pages; identified first page. https://blakefriedmann.co.uk/submissions
- Bridport short story rules: 12-point font, double spacing, page numbers centre-bottom, word count top-right, no cover/title page and no identifying details/filename. The separate novel page and consolidated rules differ on font, so do not hard-code a branded preset. https://bridportprize.org.uk/the-competition/rules-and-entry-checklist/
- Darley Anderson: Word/PDF attachments; samples may be first chapters/pages/word count. https://darleyanderson.com/submissions/

Compile selects exact section revisions in manuscript order. Output settings never mutate source writing. Notes, synopses, private history, comments and account identity are not exported. Anonymous mode removes the supplied author field, separate title page, author header and creator metadata; the writer must still inspect their own title/prose and filename for identity. Do not claim automatic anonymisation of literary content.

Word export is real OOXML .docx with specified font/size/line spacing, page geometry and a PAGE field, not HTML renamed .doc. No font files are redistributed. Print/Save as PDF uses browser printing: installed fonts, page margin boxes and print settings vary. Verify PDF font and pagination; do not label a substituted Times font as Times New Roman. The writer's recipient rules always override presets. Compile performs no AI rewriting and sends nothing externally.

## Required evidence (not satisfied merely by deploying)

- Unit/database: save/retry/conflict, exact text, snapshot/restore safety, hierarchy cycles/cross-project moves, deletion recovery, privacy, export integrity, 100,000 words/200 sections.
- Browser/API: actual workspace with synthetic sessions and isolated DB, desktop/touch/WebKit, interrupted/delayed saves, refresh, stale devices, cards, snapshot restore, compile/download. No real emails or real manuscripts.
- Real Netlify Identity/preview integration must be distinguished from an isolated test harness.
- Inspect rendered DOCX/PDF layout; verify no page clipping, correct spacing, anonymous metadata and text.
- Configure encrypted off-primary backups, document retention/restore targets and successfully restore one. Snapshots in the same database do not meet this gate.
- CI, lint/typecheck/build on the final SHA; no unresolved privacy defects; migration rollback must retain project data.
- Mark sees screenshots/recording; at most one optional five-minute writer usability check. Do not substitute repeated editor/writer/email testing.

Until these gates are recorded, this is a pilot preview, not the only home for a novel. No production flag should be enabled merely because CI turns green.

## Rollback

Set WRITER_PROJECTS_ENABLED=false and redeploy the known-good application. Retain project tables and data; do not drop them. Existing v1.2 submission/privacy policies are unchanged by migrations 007–008. Never rewrite an applied migration: use a new additive correction.
